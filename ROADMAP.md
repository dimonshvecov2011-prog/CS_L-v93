# План развития

Этот документ разделяет подтверждённое состояние и предлагаемые следующие шаги. Номера будущих версий — рабочая цель, а не обещание даты выпуска. Любой релиз требует отдельной проверки и публикации.

## Текущее состояние

- **CS:L 0.3.2** — это текущая версия исходников в `main`. Для неё пока нет тега `v0.3.2` и публичного GitHub Release.
- **CS:S v93** — Source SDK-модификация в разработке. Сборка Client/Server Win32 проходит в CI, но полноценный запуск клиента ещё требует диагностики: зафиксировано падение после `Initializing renderer`.
- **Равные условия** — сторонний менеджер модов и пользовательская установка изменений не входят в план. Профили — только контролируемые настройки проекта; оригинальные файлы Steam не модифицируются.

## CS:L — следующие версии

### 0.3.3 — стабилизация и эксплуатационная готовность (предварительный план)

- Завершить аудит `Classic`, `Modern` и `Competitive`: оставить только утверждённые командой параметры и убедиться, что профили не дают игрового/соревновательного преимущества.
- Завершить безопасный канал обновления самого лаунчера: только HTTPS, ограничения размера, тайм-ауты и отмена, проверка SHA-256 и тесты; отдельно определить проверяемый и обратимый процесс применения обновления.
- Подключить список реальных серверов проекта после предоставления его поддерживаемого JSON-источника; демонстрационные `127.0.0.1` не выдавать за рабочие серверы.
- Улучшить диагностику: показывать путь и состав архива, не включать файлы игры, и ясно предупреждать пользователя перед передачей архива.
- Проверить пользовательские сценарии на Windows: установка, повторный поиск, запуск, смена профиля, ошибка сети и повреждённые настройки.

### 0.4.x — развитие только после стабилизации 0.3.x

- Уточнить состояние профилей и настроек, обновления и серверного списка по результатам использования 0.3.x.
- Рассматривать только функции, совместимые с единым игровым составом: не добавлять публичный каталог пользовательских модов и не изменять клиентские файлы Valve.
- Публиковать конкретный набор функций и номер версии после согласования объёма, а не считать этот пункт уже утверждённым релизом.

## CS:S v93 — технический план

1. Выполнить A/B-проверку падения: повторить запуск с согласованным `gameinfo.txt` и базовым контентом, сравнить DLL CSS93 со штатными HL2MP DLL из CI.
2. По результату локализовать причину между SearchPaths/контентом движка и CSS93 DLL; при необходимости собрать Debug-вариант без линкерного workaround и проверить с PDB.
3. Повторить проверку запуска клиента, карты и локального подключения на Windows и обновить [известные проблемы](docs/known-issues.md) фактическими результатами.
4. Только после стабильного запуска переходить к дальнейшей игровой функциональности: движение, оружие, раундовая логика и HUD.

Сборочные требования и проверяемая процедура описаны в [docs/build.md](docs/build.md).
