# План развития

Этот документ разделяет подтверждённое состояние и предлагаемые следующие шаги. Номера будущих версий — рабочая цель, а не обещание даты выпуска. Каждый релиз требует отдельной проверки и публикации.

## Текущее состояние

- **CS:L 0.3.6** — hotfix-кандидат: исправляет SearchPaths, из-за которых штатные VPK-файлы ошибочно считались отсутствующими; Windows CI требуется перед публикацией.
- **CS:L 0.3.5** — опубликованный этап стабилизации: backup/restore настроек, транзакционные профили, recovery UI, safe mode, single-instance и тестируемый rollback updater-а на fake channel. Реальный updater feed остаётся выключенным.
- **CS:L 0.3.3** — предыдущая версия с адаптивной WPF-оболочкой и hardening базовых сервисов.
- **CS:L 0.3.2** — состояние исходников до этого релизного кандидата; для этой версии ранее не было тега/публичного релиза.
- **CS:S v93** — Source SDK-модификация в разработке. Сборка Client/Server Win32 проходит в CI, но полноценный запуск клиента ещё требует диагностики: зафиксировано падение после `Initializing renderer`.
- **Равные условия** — сторонний менеджер модов и пользовательская установка изменений не входят в план. Профили — только контролируемые настройки проекта; оригинальные файлы Steam не модифицируются.

## CS:L 0.3.6 — исправление SearchPaths

- Указывать SearchPaths на стандартные каталоги `cstrike`, `hl2` и `platform`, чтобы Source сам подхватывал VPK и loose-файлы, а профиль не требовал отдельных фиксированных VPK-имён.
- Проверять production template тестом на стандартной структуре Steam-установки; не менять содержимое игры.
- Согласовать версию, installer, документацию и Windows CI перед тегом `v0.3.6`.

## CS:L 0.3.5 — стабильность, резервирование и восстановление

- Не добавлять новых пользовательских игровых функций; сосредоточиться на сохранности настроек, профиля и возможности вернуться к последнему рабочему состоянию.
- Сохранять пять последних копий `settings.json`, предлагать последнюю валидную копию после повреждения, поддерживать подтверждаемое восстановление.
- Собирать профиль в staging, валидировать SearchPaths только внутри FileSystem, не пересобирать неизменившийся профиль и сохранять его пользовательские файлы; factory reset создаёт чистую копию, оставляя прежний профиль в backup.
- Показывать recovery prompt после аварийного закрытия, поддерживать `--safe-mode`, подтверждаемый factory reset и межсессионный Windows mutex, именованный по SID пользователя.
- Проверять игру и профиль перед запуском; ограничивать диагностические логи, пропускать symbolic links и включать в архив только inventory резервных копий.
- Транзакционный updater тестируется на фейковом канале; рабочий feed пустой. Не включать самообновление игрокам, пока не появится отдельный Windows bootstrapper и зелёная интеграционная проверка.
- Для релиза используются read-only permissions на build/test job и отдельный tag-only job с правом публикации.

## CS:L 0.3.3 — предыдущий релиз

- Полный редизайн адаптивной WPF-оболочки, исправление перемещения/изменения размера окна, проверка границ элементов и состояния при узком рабочем столе.
- Безопасный канал загрузки архива updater-а: HTTPS, размеры и SHA-256; отмена сетевого запроса сохраняется. Архив только скачивается и проверяется; автоматическая распаковка или замена игровых/лаунчерных файлов этим релизом не добавляется.
- Безопасное сохранение неизвестной версии схемы настроек, ограничение пути запуска executable директорией игры (включая symlink target), лимит oversized-записи и ротация логов, исправление PowerShell publish-проверки и сверка версии release tag.
- Регрессионные тесты для найденных дефектов, сборка и тестирование GitHub Actions на Windows.
- Чистка только доказанно неиспользуемого `ProfileService` и его интерфейса; остальные файлы остаются до подтверждения ненужности.

## CS:L 0.4.x — после стабилизации 0.3.x

- Проверить UX 0.3.6 на Windows при разных масштабах DPI и размерах экрана; исправить только воспроизводимые проблемы.
- Подключать реальные серверы лишь после предоставления поддерживаемого HTTPS JSON-источника; демонстрационные `127.0.0.1` не выдавать за рабочие серверы.
- Принимать новые функции только при совместимости с единым игровым составом; не добавлять публичный каталог пользовательских модов и не изменять клиентские файлы Valve.
- Публиковать конкретный набор функций и номер версии после согласования объёма, а не считать этот пункт уже утверждённым релизом.

## CS:S v93 — технический план

1. Выполнить A/B-проверку падения: повторить запуск с согласованным `gameinfo.txt` и базовым контентом, сравнить DLL CSS93 со штатными HL2MP DLL из CI.
2. По результату локализовать причину между SearchPaths/контентом движка и CSS93 DLL; при необходимости собрать Debug-вариант без линкерного workaround и проверить с PDB.
3. Повторить проверку запуска клиента, карты и локального подключения на Windows и обновить [известные проблемы](docs/known-issues.md) фактическими результатами.
4. Только после стабильного запуска переходить к дальнейшей игровой функциональности: движение, оружие, раундовая логика и HUD.

Сборочные требования и проверяемая процедура описаны в [docs/build.md](docs/build.md).
