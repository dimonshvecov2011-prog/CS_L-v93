# CS:L 0.4.0 — архитектура собственного HUD-плагина

## Статус

Это рабочая архитектура и техническое ограничение первой фазы 0.4.0. Стабильный HUD-плагин ещё не считается реализованным, пока он не загружен на реальной Steam-версии CS:S и не прошёл ручную проверку меню, карты и сервера.

Исследовательские выводы Фазы A находятся в [hud-phase-a-research.md](hud-phase-a-research.md). До подтверждения client-code loading разрешён только планируемый файловый слой `cstrike/custom/csl_hud`. Любой будущий runtime обязан иметь независимый compatibility gate: без `-insecure` он не загружается и не создаёт панели. `-insecure` означает отсутствие VAC; с HUD допускаются только серверы без VAC.

## Цель

CS:L HUD должен быть внутриигровым клиентским плагином, который имеет приоритет над штатными VGUI/HUD-панелями Source и не позволяет стандартному интерфейсу перекрывать собственные элементы. При этом плагин не должен менять оригинальные файлы Steam-игры и не должен вмешиваться в стрельбу, прицеливание, память сервера или сетевые игровые решения.

## Приоритет интерфейса

Приоритет задаётся явно в конфигурации runtime, а не случайным порядком загрузки файлов:

```json
{
  "schemaVersion": 1,
  "mode": "replace",
  "zOrder": 1000,
  "disableValveHud": true,
  "fallback": "overlay",
  "enabled": true
}
```

Правила:

1. `replace` — CS:L создаёт корневую панель поверх штатного HUD и скрывает штатные элементы, которые разрешено скрывать через поддерживаемый интерфейс.
2. `zOrder: 1000` — все панели CS:L находятся в собственном верхнем слое; конкретный API-способ установки z-order должен быть подтверждён на целевом build CS:S.
3. Если штатный HUD нельзя безопасно скрыть, используется `overlay`, а конфликтующие панели перечисляются в диагностике.
4. Если клиентский интерфейс несовместим, HUD отключается целиком. Игра продолжает запускаться без частично загруженного HUD.
5. Плагин не использует жёсткие адреса без проверки build и SHA-256 соответствующих DLL.

## Разделение компонентов

```text
CS:L Launcher
  ├─ выбирает режим HUD
  ├─ проверяет manifest и совместимость build
  ├─ подготавливает только проверенный runtime и custom/csl_hud
  └─ запускает игру

CSL-HUD runtime plugin
  ├─ compatibility gate
  ├─ engine/VGUI bridge
  ├─ HudState
  ├─ HudController
  ├─ root panel с высоким z-order
  ├─ стандартный HUD suppressor
  ├─ replace/overlay fallback
  └─ diagnostics
```

Поток данных:

```text
игровые события / разрешённые интерфейсы
                 ↓
              HudState
                 ↓
            HudController
                 ↓
          CSL root panel (z-order 1000)
```

## Минимальные панели MVP

- здоровье и броня;
- активное оружие и боеприпасы;
- команда и деньги;
- таймер раунда;
- счёт команд;
- диагностическое уведомление о fallback/несовместимости.

Каждая панель должна иметь safe-zone, масштабирование для 4:3/16:9 и возможность скрытия. Панели не должны напрямую зависеть от памяти игры: они получают нормализованный `HudState`.

## Manifest и совместимость

Плагин не будет загружаться только потому, что DLL лежит в `custom`. Перед активацией нужны:

- архитектура `win32`/`x86`, соответствующая игре;
- идентификатор и ClientVersion из `steam.inf`;
- поддерживаемый Steam build;
- версия ABI плагина;
- SHA-256 клиентских бинарников, если используются build-specific hooks;
- режим `replace` или `overlay`;
- безопасный fallback.

Пример manifest находится в `hud/hud.manifest.json`. Отсутствующий или несовместимый manifest должен выключать HUD, но не блокировать запуск CS:S.

## Фазы реализации

### Фаза A — compatibility probe

Нужно получить подтверждённый способ загрузки клиентского плагина на целевой Steam build CS:S. Проверяются VGUI, client interface и событийная модель. Неподтверждённые DLL injection и сигнатурные хуки в релиз не входят.

### Фаза B — пустой runtime

Плагин показывает только `CS:L HUD loaded`, пишет версию build/API и создаёт root panel с нужным z-order. Проверяется, что штатный HUD не перекрывает тестовую панель.

### Фаза C — локальные данные

Добавляются health/armor, weapon/ammo, team/money и round timer без серверного протокола.

### Фаза D — интеграция лаунчера

Лаунчер сможет выбрать HUD mode и проверить manifest только после появления подтверждённого способа загрузки. До этого runtime не копируется в папку игры, а пользовательская конфигурация HUD не активируется.

### Фаза E — rc1

Выпускается только после проверки на реальной установке пользователя. Smoke-check должен включать Replace, Overlay fallback, отключение HUD, меню, карту, смерть/возрождение, смену оружия и 4:3/16:9.

## Что запрещено для MVP

- изменение оригинальных VPK и DLL Steam;
- DLL injection без build gate;
- жёсткие адреса без таблицы совместимости;
- автоматический запуск на неподдерживаемом build;
- вмешательство в aim, recoil, fire, память сервера или игровые сетевые решения;
- обязательная зависимость HUD от будущего серверного протокола.

## Критерий готовности

0.4.0 не считается готовой, пока на реальной CS:S не подтверждены: приоритет собственного HUD над штатным, отсутствие визуального перекрытия, корректный fallback, запуск без HUD, загрузка карты и отсутствие ошибок в консоли. До этого допускается только `0.4.0-rc1`.
