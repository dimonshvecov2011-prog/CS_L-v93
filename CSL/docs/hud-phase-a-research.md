# CS:L 0.4.0-dev — Фаза A: исследование безопасного HUD

**Статус:** на ревью; реальный клиентский DLL-плагин в этой фазе не реализуется и не включается.

В репозитории добавлен консервативный файловый HUD v1 с `scripts/hudlayout.res`, ресурсами цветов, прицела и шрифта, manifest и SHA-256. Его установка доступна только в `cstrike/custom/csl_hud`; фактическая видимость конкретных resource-ключей ещё требует проверки на Windows CS:S v93 и не заявляется по одному наличию файлов.

## 1. Цель и границы

Цель Фазы A — определить, какая часть интерфейса CS:L может быть сделана штатными ресурсами Source, а какая требует клиентского кода. В область работы не входят обход VAC, сокрытие модуля от античита, DLL-injection в защищённый процесс, изменение aim/recoil/fire, чтение или запись памяти сервера, сетевые решения и подмена оригинальных VPK/DLL.

Безопасное правило проекта: любой будущий клиентский runtime CS:L допускается только при запуске с `-insecure`. Runtime обязан самостоятельно проверить наличие этого аргумента и завершиться до инициализации HUD, если аргумента нет. Лаунчер при включённом CS:L HUD принудительно добавляет `-insecure`; этот параметр нельзя отключить отдельным флажком. `-insecure` не является способом обхода VAC: это явный отказ от VAC и режим только для серверов без VAC.

## 2. Файловый HUD в `custom/csl_hud`

Предлагаемый собственный каталог:

```text
<GameRoot>/cstrike/custom/csl_hud/
├── resource/                 # VGUI/HUD resource definitions (*.res)
├── scripts/hudlayout.res    # расположение и параметры HUD-панелей
├── materials/               # только собственные материалы, если они нужны
├── resource/fonts/          # только лицензированные/собственные шрифты
└── cfg/                     # только явно согласованные конфигурационные файлы
```

Source поддерживает загрузку пользовательских файлов через `cstrike/custom`. Это позволяет не менять `gameinfo.txt`, VPK и DLL. Лаунчер должен создавать, обновлять и удалять **только** `cstrike/custom/csl_hud`, предварительно проверяя, что путь канонически находится внутри ожидаемого `cstrike/custom`. Удаление чужих файлов и обход символических ссылок должны быть запрещены.

Это всё же исключение из строгого правила «не трогать папку Steam»: каталог находится внутри Steam-установки CS:S. Исключение ограничено одним собственным каталогом `custom/csl_hud`; оригинальные VPK/DLL, `gameinfo.txt` и чужие каталоги не изменяются. До реализации управления файлами это ограничение должно быть явно принято пользователем.

### Что реалистично сделать ресурсами

* расположение, видимость, размеры и базовые параметры существующих HUD-панелей через `scripts/hudlayout.res`;
* подписи, цвета, шрифты, иконки и часть layout-параметров через `resource/*.res`;
* собственные VGUI-панели только там, где конкретная версия клиента уже умеет создать соответствующий класс/элемент по resource-описанию;
* отдельные материалы и лицензированные шрифты, если формат и путь поддерживаются текущим клиентом;
* параметры стандартного прицела и связанные с ним пользовательские настройки в пределах реально поддерживаемых данной сборкой файлов.

### Что ресурсами не гарантируется

Resource-файлы не создают произвольную игровую логику, не добавляют новый C++-класс панели, не получают данные о сервере, игроках или оружии, не реализуют протокол, не выполняют сетевые запросы и не перехватывают игровые события. Нельзя считать произвольную строку в `.res` доказательством поддержки: конкретный ключ должен быть проверен на CS:S v93 с чистым резервируемым custom-каталогом.

## 3. Варианты клиентского кода

### Подписанный Source client plugin API

Документация Valve Developer Community указывает, что клиентские плагины Source требуют подписи Valve; `-insecure` используется для разработки. Это не универсальный способ доставить неподписанный production-плагин в официальную CS:S. Для текущего build нужно отдельно подтвердить точный API и механизм подписи, но проект не должен обходить проверку подписи.

### Source SDK/mod client code

Исходники Source SDK 2013 показывают штатную архитектуру клиентского HUD/VGUI (`src/game/client`, `hud.h`, client factory). Такой код обычно является частью собранного клиентского кода мода/ветки движка, а не безопасно подключаемым файлом к официальному бинарнику CS:S. Распространение чужих файлов Valve запрещено; сборка собственного SDK-мода должна рассматриваться как отдельный продукт с отдельными файлами и совместимостью, а не как DLL для подмены официального клиента.

### Загрузка DLL в официальный процесс

Инъекция или иная загрузка неподписанной DLL в официальный процесс не принимается в проект: это меняет процесс игры, может быть замечено античитом и противоречит запрету на обход VAC. Даже при `-insecure` это не становится автоматически безопасным. Никаких жёстких адресов, хуков, патчей памяти, подмены оригинальных DLL и скрытия загрузчика не использовать.

### Вывод для текущего build

Подтверждённый безопасный путь Фазы A — файловый HUD в `custom/csl_hud` плюс явный `-insecure` safety gate в лаунчере и будущем runtime. Рабочий способ загрузки собственного клиентского DLL в официальный текущий build этой фазой не доказан и не должен имитироваться manifest-заготовкой. До написания настоящего плагина требуется Windows-проверка на тестовой установке с `-insecure`, без VAC-серверов и без основного аккаунта.

## 4. План проверки до runtime

1. Зафиксировать `ClientVersion` и архитектуру из реальной установки (`steam.inf`, исполняемый файл и результаты Windows-проверки).
2. Создать резервную копию только текущего состояния `custom/csl_hud` и установить минимальный собственный набор ресурсов.
3. Запустить официальную CS:S только с `-insecure`, проверить меню, локальную карту и отсутствие ошибок загрузки; не подключаться к VAC-серверам.
4. Поочерёдно добавлять `.res`, `hudlayout.res`, шрифт и материал, фиксируя результат и откатывая последний файл при ошибке.
5. Проверить, что лаунчер не изменил VPK/DLL/`gameinfo.txt`, а удаление отключённого HUD затрагивает только собственный каталог.
6. Отдельно проверить отрицательный gate будущего runtime: запуск без `-insecure` не загружает модуль и не создаёт HUD.

На текущем sandbox нет реальной Windows-установки CS:S, поэтому интерактивное WPF-окно и реальная загрузка HUD здесь не подтверждены.
