# CS:L 0.3.6 — исправление SearchPaths профиля

Windows-лаунчер для текущей Steam-сборки Counter-Strike: Source. Совместимость определяется по версии клиента из `cstrike/steam.inf`, а Steam `buildid` используется как дополнительная диагностическая информация. Файлы Valve в репозитории отсутствуют.

## Подтверждённые значения текущей копии

В предоставленных файлах обнаружено:

```text
steam.inf:
PatchVersion=11003710
ClientVersion=11003710
ServerVersion=11003710
ProductName=cstrike
appID=240
ServerAppID=232330

appmanifest_240.acf:
buildid=25338318
TargetBuildID=25338318
```

`11003710` и `25338318` — разные идентификаторы. Поэтому лаунчер сравнивает `ClientVersion`/`PatchVersion` с `knownVersions`, а не с `knownBuilds`.

## Сборка

Требуется Windows 10/11 и .NET 8 SDK:

```powershell
dotnet restore
dotnet build CssLauncher.sln -c Release
dotnet test tests/CssLauncher.Tests/CssLauncher.Tests.csproj
```

Запускаемый проект — `src/CssLauncher.App/CssLauncher.App.csproj`. WPF-приложение предназначено для Windows.

## Манифест совместимых версий

`config/version-manifest.v93.json`:

```json
{
  "schemaVersion": 2,
  "game": "Counter-Strike Source",
  "version": "11003710",
  "knownVersions": [11003710],
  "knownBuilds": [25338318],
  "enableSha256Checks": false,
  "variants": []
}
```

`knownVersions` — список допустимых значений `ClientVersion`/`PatchVersion` из `steam.inf`. Если значение есть в списке, статус — `Confirmed`. Если список пуст, статус — `ManifestEmpty`. Если `steam.inf` найден, но версия отсутствует в списке, статус — `UnknownBuild`; запуск доступен только в диагностическом режиме.

`knownBuilds` хранит ожидаемые Steam `buildid` только для информации и будущих проверок обновлений. Он не сравнивается с `ClientVersion`.

SHA-256 оставлена как дополнительная проверка. Чтобы включить её, установите `enableSha256Checks` в `true` и добавьте варианты с корректными SHA-256 в `variants`. При расхождении лаунчер показывает список файлов и требует отдельного подтверждения перед запуском; включённая, но пустая/некорректная SHA-конфигурация блокирует запуск вместо молчаливого пропуска проверки. По умолчанию SHA-256 выключена, потому что Steam-файлы могут изменяться при обновлениях.

## Как узнать идентификаторы

В консоли игры выполните:

```text
version
```

Сохраните `Build Label` и `Client/Server version`. Основной номер для лаунчера берётся из:

```text
<GameRoot>\cstrike\steam.inf
```

Нужны строки `ClientVersion` и `PatchVersion`. Steam-номер берётся из:

```text
<SteamLibrary>\steamapps\appmanifest_240.acf
```

Нужна строка `buildid`. Если Steam обновил игру, добавьте новый номер `ClientVersion`/`PatchVersion` в `knownVersions`, а соответствующий Steam `buildid` запишите в `knownBuilds`.

## Исполняемый файл и Steam

Лаунчер ищет `cstrike.exe` и `hl2.exe`, показывает найденные варианты и сохраняет выбранный exe; при единственном варианте список отображается без необходимости выбора. Допускаются только эти имена в корне найденной игры; произвольные пути к executable отклоняются. По умолчанию используется `cstrike.exe`. В запуск добавляется `-steam`, если установлен соответствующий флажок; он включён по умолчанию. Отсутствие процесса Steam вызывает предупреждение, но само по себе не является авторизацией или проверкой лицензии.

## Ручная проверка профиля

Подробная пошаговая инструкция с проверкой обоих exe, команд `path` и `version`, а также загрузки из `custom/` находится в [docs/manual-check-game-launch.md](docs/manual-check-game-launch.md).

Профили CS:L создаются в `%AppData%\CssLauncher\profiles\<id>\`. Выбранный профиль общий для вкладок обзора и профилей, сохраняется в настройках и определяет `-novid`, `-console`, `-windowed`, `-noborder` и дополнительные аргументы. При отсутствии выбранного exe лаунчер автоматически предпочитает `cstrike.exe`, а затем `hl2.exe`.

```bat
cstrike.exe -steam -game "%AppData%\CssLauncher\profiles\classic" -novid -console
```

Или:

```bat
hl2.exe -steam -game "%AppData%\CssLauncher\profiles\classic" -novid -console
```

Если потребуется изменить порядок или `custom/*`, изменяйте только `templates/gameinfo.template.txt`, а не код.

## Обновление игры

Если Steam обновил игру до новой `ClientVersion`, а встроенные расширения проверялись для версии `11003710`, лаунчер сообщает и пишет в лог:

> Установлена ClientVersion X, встроенные расширения проверены для версии 11003710. Возможна несовместимость.

Автоматической миграции или блокировки обновлений на этом этапе нет.

## Ограничения безопасности

Лаунчер не изменяет оригинальную папку игры, не распространяет файлы Valve и не требует администратора. Пути из манифеста проверяются как относительные. Аргументы передаются через `ProcessStartInfo.ArgumentList`, поэтому пробелы и кириллица в путях не требуют ручного экранирования.

Профиль и настройки находятся в `%AppData%\CssLauncher\`. Логи — в `%AppData%\CssLauncher\logs\`.


## Возможности текущего лаунчера

В приложении есть бренд **CS:L**, тёмная игровая оболочка, поиск полноценных установок по Steam-библиотекам и кнопка **«Установить через Steam»**. Кандидат должен содержать `cstrike/gameinfo.txt` и один из поддерживаемых exe; поиск продолжает проверку следующих библиотек при пустом или неполном каталоге. Кнопка открывает официальный URI `steam://install/240`; саму игру, лицензию и файлы Valve загружает только Steam. Во время ожидания виден статус установки и действие повторной проверки; папку можно выбрать вручную.

Обычному пользователю не нужны команды PowerShell: достаточно установить Steam, установить CS:S через кнопку в CS:L и нажать **«ИГРАТЬ»**. При необходимости можно выбрать папку вручную. CS:L не копирует и не изменяет оригинальные файлы игры.

Автоматически создаются:

```text
%AppData%\CssLauncher\profiles\classic\custom
%AppData%\CssLauncher\backups
%AppData%\CssLauncher\logs
```

## Профили и ограничения

`Classic`, `Modern` и `Competitive` — фиксированные пресеты параметров запуска, а не плагины или менеджер модов. В проекте нет каталога и установщика сторонних модификаций; `custom` зарезервирована под контролируемые ресурсы проекта, а оригинальная папка Steam не изменяется. Менеджер пользовательских модов не входит в план: игровые условия должны оставаться равными.

## Сборка установщика Windows

Для self-contained публикации на Windows с установленным .NET 8 SDK выполните:

```powershell
.\installer\publish.ps1
```

Результат появится в `artifacts\publish\win-x64`. Чтобы собрать красивый установщик, установите [Inno Setup](https://jrsoftware.org/isinfo.php), затем выполните:

```powershell
iscc .\installer\CSL-Setup.iss
```

Готовый файл появится в `artifacts\installer`. В установщик попадает только приложение CS:L и документация; файлы Counter-Strike: Source, Steam и Valve туда не включаются.

## Автоматическая сборка через GitHub Actions

Файл `.github/workflows/build-csl.yml` собирает проект на `windows-latest` без установки .NET или Inno Setup на компьютере разработчика. Workflow выполняет restore, build, тесты, self-contained publish и собирает `CSL-Setup-0.3.6.exe`; перед релизом версия тега сверяется с версиями приложения и установщика. Готовые portable-файлы и установщик доступны во вкладке **Actions → Artifacts**.

Для релизной сборки создайте и отправьте тег:

```powershell
git tag v0.3.6
git push origin v0.3.6
```

Для тега `v*` workflow дополнительно создаёт GitHub Release и прикладывает установщик. Сам репозиторий не должен содержать файлы CS:S, Steam или Valve.

## CS:L 0.3.5 — backup, rollback и безопасное восстановление

- Перед каждой перезаписью `settings.json` сохраняются timestamped-копии; остаются последние пять валидных файлов в `%AppData%\CssLauncher\backups\settings`. Откройте вкладку **«Восстановление»**, выберите копию и подтвердите восстановление. При повреждённом или чрезмерно большом JSON CS:L предлагает последнюю рабочую копию; исходный файл сохраняется отдельно.
- Профили создаются сначала в staging-каталоге под `%AppData%\CssLauncher\profiles`, `gameinfo.txt` и SearchPaths внутри `FileSystem` проверяются до установки, прежняя версия переносится в `%AppData%\CssLauncher\backups\profiles`. Уже валидный профиль повторно используется; при обновлении шаблона его `cfg`/`custom` и другие файлы сохраняются. Подтверждённый factory reset создаёт чистый профиль, оставляя прежний целиком в backup. Вкладка восстановления даёт откат только после проверки выбранной копии.
- **Factory reset** находится на вкладке восстановления и требует явного подтверждения. Он сбрасывает локальные настройки/профили CS:L; игровые файлы не меняются.
- После некорректного завершения при следующем запуске показывается предложение открыть восстановление. Для диагностики можно запустить `CSL.exe --safe-mode`: игровой запуск, поиск игры и проверка обновлений отключены, доступны локальные действия восстановления.
- Одновременно допускается один экземпляр лаунчера для текущего пользователя, включая параллельные Windows-сессии. Логи ограничены размером, числом файлов и ротацией по UTC-дате; диагностический ZIP содержит inventory backup-файлов, но не вкладывает содержимое резервных копий целиком и пропускает symbolic links.
- Перед **каждым** запуском повторно проверяются ClientVersion/состояние файлов и целостность профиля. Изменения требуют предупреждения и явного выбора; если профиль повреждён, он не запускается молча.
- Для локальной проверки используйте `dotnet build CssLauncher.sln -c Release -p:EnableWindowsTargeting=true` и `dotnet test tests/CssLauncher.Tests/CssLauncher.Tests.csproj -c Release`. WPF нельзя интерактивно проверить в Linux.

Updater transaction engine покрывается fake-channel тестами: пакет проходит проверку размера/SHA-256 и staging, предыдущая версия сохраняется, а при отказе/таймауте health confirmation выполняется rollback. **Игровой update channel остаётся пустым и выключенным; текущий интерфейс не применяет обновления.** Запуск новой версии из Windows требует отдельного bootstrapper-а, поэтому самообновление не включено игрокам.

## CS:L 0.3.6 — исправление запуска профиля

- Шаблон `gameinfo.txt` передаёт Source реальные каталоги `cstrike`, `hl2` и `platform`, а не фиксированные имена отдельных VPK-файлов, которые могут отсутствовать. Движок сам находит VPK-архивы в этих каталогах.
- Добавлен regression-тест на production template: корректный профиль генерируется для обычной структуры установки с этими каталогами даже без файлов с прежними предполагаемыми именами VPK.
- Лаунчер не меняет и не переносит файлы Steam; меняется только профиль CS:L в `%AppData%`.

## CS:L 0.3.3 — интерфейс и hardening

- Полностью обновлена WPF-оболочка; панели прокручиваются по вертикали, параметры запуска переносятся, а боковая панель скрывается на узком рабочем столе.
- Окно перемещается перетаскиванием заголовка; добавлены кнопки свернуть/развернуть/закрыть, двойное нажатие по заголовку переключает максимизацию. Начальный размер ограничен рабочей областью экрана.
- Updater читает локальный camelCase JSON без зависимости от регистра, принимает только HTTPS для удалённых манифестов и загрузок, проверяет конечный URL, SHA-256 и точный размер; ограничены размер манифеста и архива, отмена запроса вызывающим кодом сохраняется. Загрузка не распаковывает и не заменяет файлы игры.
- Неизвестный `schemaVersion` настроек сохраняется без изменения; логи ограничены размером файла, включая отдельную oversized-запись, ротацией и числом файлов, исключения записываются с полной информацией.
- Запуск ограничен двумя поддерживаемыми executable из корня игры; символьные ссылки на файлы за пределами каталога отклоняются. Сведения `knownBuilds` отделены от проверки `ClientVersion`. Удалён доказанно неиспользуемый дублирующийся `ProfileService`.
- `publish.ps1` проверяет код возврата `dotnet publish` и наличие `CSL.exe`; версия приложения и установщика повышена до 0.3.3.

Кросс-сборка и тесты выполняются в CI на Windows. Интерактивную визуальную проверку WPF и размеры на разных DPI необходимо подтвердить на Windows.

## CS:L 0.3.2 — исправления и проверяемый функционал

В версии 0.3.2 три профиля запуска (`Classic`, `Modern`, `Competitive`) синхронизированы между вкладками, а выбранный ID восстанавливается из настроек с безопасным fallback на `Classic`. Запуск блокируется на всё время работы процесса игры, чтобы предотвратить повторный запуск. Настройки записываются через временный файл и замену; повреждённый JSON сохраняется как `.bak`, а ошибка при закрытии предлагает повторить сохранение, закрыть без сохранения или остаться в приложении.

Серверный список поддерживает локальный JSON и HTTPS-источник; удалённый HTTP запрещён. В комплекте есть `config/servers.example.json` как демонстрационный формат. Профили управляют настройками запуска CS:L; каталог `custom` зарезервирован для собственных ресурсов проекта и не управляется как каталог сторонних модификаций.

В 0.3.2 локальный канал обновлений был неактивен; hardening этих проверок выполнен в 0.3.3. В текущем `config/launcher-update.json` download URL и хэш намеренно пусты, поэтому автообновление не предложит неподготовленный пакет. Диагностический архив собирается в `%AppData%\\CssLauncher\\backups` в фоновом потоке и включает настройки, логи, сведения о версии Steam и выбранный встроенный профиль без копирования игровых файлов Valve.

Конфигурации копируются в output автоматически: `servers.example.json` и `launcher-update.json`. Для локальной проверки из Linux используйте `dotnet build CssLauncher.sln -c Release -p:EnableWindowsTargeting=true` и `dotnet test tests/CssLauncher.Tests/CssLauncher.Tests.csproj`; запуск и интерактивную визуальную проверку WPF выполняйте на Windows. Итоговую Windows-сборку и установщик создаёт GitHub Actions.
